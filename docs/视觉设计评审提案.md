# 「日新辑览」整体视觉设计评审提案（A 版「编辑墨线」深化）

> **评审说明与执行纪律**：
> 1. 本轮只出方案、**不动手改动任何现有代码**（`public/index.html` 与 `public/style.css` 保持完全冻结）；
> 2. 严格坚守 **A 版「编辑墨线」** 核心身份：米纸底、墨线勾边、粗衬线大标题、杂志编辑排版感；坚决不换风格，坚决不要圆角糖果风、玻璃拟态、深色科技风；
> 3. 配色变量的日间值与夜间「沉墨」值均已定版，**绝不改动任何色值本身**，仅在既有变量体系内推敲层次、对比、留白与线条用法；
> 4. 站标（书与朝日）、页脚两行落款、分类副标题「第 X 辑」编号、后台分类表居中，**均恪守不动**；
> 5. **不重复刚做完的那批改进**（卡片悬停过渡、长站名截断、搜索空状态折页、分区标题线居中、键盘焦点圈、移动端双吸顶错峰）。

## 一、首屏头部（站名、搜索、计数）

### 提案 1.1：工具栏视觉降噪，从「全员重装板砖争霸」重构为「主次分明的书斋案几」
* **① 现在长什么样、有什么别扭**：
  在主搜索栏这一行（`.toolbar`），搜索框、添加网站、紧凑模式切换、导入书签一字排开，全员采用了统一的 56px 巨型高度、3px 纯黑厚边框配 5px 实体厚黑硬投影。四个控件像四块笨重的黑色实心砖头整整齐齐塞在屏幕正中，严重喧宾夺主。「导入书签」一年用不上几次，却跟每天高频使用的核心搜索框、添加主按钮平起平坐，分量相同、抢夺视线，首屏显得板滞、笨重、缺乏文人编辑版面应有的轻重呼吸感。
* **② 打算怎么改**：
  构建「主中枢（搜索）+ 主操作（添加，朱砂实色）+ 辅助工具（紧凑切换、导入书签）」的三级视觉层次：
  1. 搜索框保持全行最核心的大气主轴地位；
  2. 「添加网站」保持醒目的赭石实色块（`var(--ochre)`），作为全行唯一的彩色主焦点；
  3. 「紧凑模式」与「导入书签」做轻量化降噪——边框从 3px 粗削减为 1.5px/2px，取消 5px 凸起的大黑块硬投影，改为干净的平按键或 2px 微墨线投影，让高频与低频工具各安其位。
* **③ 改完是什么效果**：
  一眼看过去，正中间的搜索框和红彤彤的「添加网站」印章最抓人、最容易找到；而紧凑切换和导入按钮变成了右侧安静精致的配角小工具，不再像两块沉重的秤砣跟主搜索框抢戏。整个首屏工具栏从「排成一排的粗重砖头」变成了典雅有序的「书房案头工具匣」。
* **④ 代价与风险**：
  极小。纯 CSS 视觉层级调整（微调 `.toggle-view-btn` 与 `.tool-btn` 的描边和阴影分量），完全不改动 DOM 结构，也不影响按钮的点击交互与导入功能。

### 提案 1.2：大报头右上角印章语义与视觉双重撞车（「日新辑览」旁复读「辑览」印）
* **① 现在长什么样、有什么别扭**：
  大报头主标题赫然写着 80px 的粗衬线「日新辑览」，但紧随其后右上角倾斜悬挂的红底白字小印章（`.mast-seal`）里面刻的居然又是「辑览」二字！标题已经叫日新辑览，旁边又盖个辑览章，语义上等于原地复读；更别扭的是，这个印章用了 `transform: rotate(-3deg) translateY(-30px)` 强行往上拽，在不同设备屏幕与字体渲染时，极易悬空漂浮或与上方的眉题（「收 集 · 整 理 · 每 日 常 用」）互相撞车。
* **② 打算怎么改**：
  1. 将印章文案从重复的「辑览」提炼为更具金石藏书楼意蕴的题跋/鉴赏词汇，如「藏本」、「珍藏」、「常览」或「手泽」，真正起到藏书章的压角点睛效果；
  2. 样式上采用基于文字基线的自然挂角排版，收敛生硬的负 30px 位移，让印章稳稳当当压在大标题末尾的右上肩。
* **③ 改完是什么效果**：
  标题右上角不再是滑稽的「日新辑览……辑览」复读，而是端端正正扣着一枚朱砂小方印「藏本」（或「手泽」），红黑掩映，既有古籍藏书楼的文雅书卷气，又像古人手校刊印的鉴赏印，整体格调瞬间立住。
* **④ 代价与风险**：
  极小。仅改动 `public/index.html` 报头处印章的 2 个汉字，以及 `public/style.css` 中微调两行挂角定位。不涉及任何脚本。

### 提案 1.3：报头右侧边栏刊期与统计字形排版散乱
* **① 现在长什么样、有什么别扭**：
  大报头右侧是公历日期、农历黄历和收录统计。现在的公历日期使用了罕见的 `24.5px` 半像素字号；农历用了一个浅红底带框的圆角小胶囊（`.almanac-badge`），像现代手机 App 里的打卡标签；底下的收录站点数虽然标红加粗，但在字体上没做等宽数字设定，文字与数字忽粗忽细、间距发散；整块右侧栏虽然用一根 3px 黑竖线隔开，但各行元素字号跨度大（从 24.5px 跳到 14.5px 再到 11px），缺乏传统报纸「发刊号/刊期报头」的版面编排严谨感。
* **② 打算怎么改**：
  1. 规范字号层级（公历归整为 22px 经典粗衬线宋体），农历黄历去胶囊化——取消浅红背景和圆角细框，改用两道细墨线夹衬，以「岁次丙午 · 农历九月初六 · 寒露」的纯正报刊刊期格式平铺；
  2. 统计数字（`#siteCount`、`#catCount`）统一引入等宽数字支持（`font-variant-numeric: tabular-nums`），与左侧日新辑览标题形成「左主书名、右司刊期」的经典大报报头对位。
* **③ 改完是什么效果**：
  报头右上角不再像散落的几条现代提示文字，而是变成了像《申报》《大公报》或民国老杂志卷首那样工整耐看的「刊期栏」：左边是沉稳的粗衬线报头，右边是规规矩矩的节气与卷帙统计，排版严密、一气呵成。
* **④ 代价与风险**：
  极小。仅微调报头右侧文本容器的 CSS 边距与字体样式，JS 动态更新日期与数字逻辑完全不变。

## 二、置顶区（Pinned Essentials / 常用常顾）

### 提案 2.1：虚线边框像「优惠券裁剪线/待上传占位区」，缺乏常顾典藏的尊崇感
* **① 现在长什么样、有什么别扭**：
  常用常顾区（`.pinned-section`）外围框着一圈 `2px dashed rgba(158, 71, 42, 0.4)` 的红棕色虚线。在现代网页交互中，大面积的矩形虚线框几乎 100% 被用于「拖拽文件上传区」或「草稿占位符」；在报刊印刷中，虚线也多代表「裁剪撕开处」。用户高频置顶的站是站长最心爱、最日常的门面，套在虚线框里显得像个临时搭的临时棚子或未完成的占位区，极其轻飘。
* **② 打算怎么改**：
  弃用现代 UI 里的虚线框，改用传统木刻雕版或精装杂志特稿常用的「子母墨线框」（外粗内细的双层实线框，利用 `outline` + `border` 组合），或者在四角加入干净利落的中式折角墨线（拐子纹折角标），底色依然沿用现有的 `--pinned-bg`。
* **③ 改完是什么效果**：
  常用常顾专区立刻从「待上传的虚线文件框」，蜕变为像线装书封皮题签、或者精装报刊「卷首精粹 / 特选头条」一样的独立典雅展台。一眼扫过去，既能看出它是独立于常规分类的特选专区，又与整站硬朗平直的编辑墨线严丝合缝。
* **④ 代价与风险**：
  极小。仅改动 `.pinned-section` 的边框渲染方式，不改任何卡片和逻辑。

---

### 提案 2.2：标题打字机五角星（★）廉价生硬，与金石墨规格格不入
* **① 现在长什么样、有什么别扭**：
  「常用常顾」标题前面直接顶着一颗纯黑体五角星 `★`（`.section-star`）。这个五角星是浏览器原生收藏夹、电商打分里最泛滥的通用字符，没有任何字体修饰，直接放在粗衬线汉字和纯中式「常用常顾」旁边，显得极其草率敷衍，宛如随手打出来的草稿符号。
* **② 打算怎么改**：
  将生硬的五角星替换为具有编辑出版、文人藏书意象的专有金石印戳——例如中式花草方印「❖」、四芒雅致星标「✦」、或一枚精致微小的「常顾」朱砂小印章（与大报头印章相呼应）；或者直接取消孤立符号，用纯正的编辑排版强化「开卷首选」的端庄感。
* **③ 改完是什么效果**：
  专区标题前不再是一颗冷冰冰的浏览器同款小星星，而是变成了一枚古雅小巧的朱红金石押花，沉静而讲究，整个置顶区的提头气质立刻脱离了廉价的“网页快捷方式感”。
* **④ 代价与风险**：
  零风险。仅替换 HTML 中单字符或通过 CSS 渲染伪元素，没有任何功能副作用。

## 三、分类分区与卡片（Sections & Cards）

### 提案 3.1：卡片图标框「方中带圆（圆角 9px）」与全站硬直墨线风骨割裂
* **① 现在长什么样、有什么别扭**：
  「编辑墨线」风格的核心灵魂是米纸底、墨线勾边、直角硬朗的报刊杂志风。整站的卡片外框、搜索框、工具栏、边栏全都是利落的直角矩形，没有任何圆角。然而，每张卡片左侧的图标底座（`.icon-box`）却被设置了 `border-radius: 9px`！这直接把 iOS/macOS 风格的软萌圆角图标塞进了刚硬利落的墨线书签框里；更尴尬的是，一旦图标加载失败变成首字兜底牌（`.icon-fallback`），圆角又突然变成了 `6px`。满屏直角中突兀冒出一堆圆角胶囊方块，风格严重割裂打架。
* **② 打算怎么改**：
  将图标框从圆滑的 9px 现代圆角，统一回归为硬朗规整的直角墨线小方牌（`border-radius: 0` 或微雕的 2px 极微倒角），外围用精致的 1.5px 墨线严谨勾边，与卡片本体的直角外框形成同构呼应。
* **③ 改完是什么效果**：
  卡片左边的图标小方块，不再像从苹果手机桌面上抠下来的圆角 App 图标，而像一枚枚整整齐齐嵌在米纸框里的铅字印版或藏书小票，全站从外框到内胆风格高度纯粹统一，彻底抹平了“直角外壳套圆角内胆”的杂糅感。
* **④ 代价与风险**：
  极小。仅改动 `.icon-box` 的圆角属性，涉及代码 2 行，不影响图标图片显示与加载容错。

---

### 提案 3.2：自定义书签删除按钮（✕）与外链小箭头（↗）重叠挤占
* **① 现在长什么样、有什么别扭**：
  在用户通过前台自行添加的书签卡片中，会渲染一个删除按钮 `.card-del`（`✕`）。它的定位是 `top: 4px; right: 6px; absolute`；而卡片站名自带的外部链接指示箭头 `.card-arrow`（`↗`）也在站名右上侧。这就导致一旦用户鼠标滑到卡片右上角准备点击打开网站时，删除按钮几乎正好压在小箭头头顶上，两者挤在弹丸之地，极易引发误触删除；视觉上两个符号挤在一起也显得十分促狭。
* **② 打算怎么改**：
  调整删除按钮的交互与排版位置：平素默认保持半透明隐蔽或作为卡片底部的微弱管理动作；或者将删除按钮规整下沉到卡片右下角、或与域名同一行的末端，与右上角象征“打开外链直达”的小箭头彻底拉开对角线距离。
* **③ 改完是什么效果**：
  右上角只留下干干净净的直达小箭头 `↗`，用户随手点击卡片右上角绝不会误点到删除；而红色的删除小叉叉老老实实待在不碍事的角落，主次分明，再无碰撞挤塞之感。
* **④ 代价与风险**：
  小。调整 `.card-del` 的定位坐标与透明度，不影响删除确认弹窗与数据删除逻辑。

---

### 提案 3.3：紧凑模式下列数过多导致 4px 厚实体阴影沦为「黑色污渍」
* **① 现在长什么样、有什么别扭**：
  当用户切换到「紧凑模式」时，网格被压缩为单行 5 列，卡片高度降到 40px 上下。但在 CSS 中，紧凑卡片依然继承了舒适模式下那个重达 `4px 4px 0 rgba(39, 36, 34, .92)` 的黑色大实体投影。在卡片密集平铺的一屏几十个格子里，每一张小卡片右下角都拖着一大块厚重的实心黑影，黑影在狭小的格子缝隙（gap: 10px）里几乎连成了片，导致整个紧凑视图看起来像铺满了黑色小煤块，失去了字典索引本应有的干练清爽。
* **② 打算怎么改**：
  在紧凑模式下（`.compact-view .card`），将粗重的 4px 厚实影轻量化为精巧的 `2px 2px 0 var(--border-line)` 或 `2px 2px 0 var(--ink)`，外边框从 2px 细化为 1.5px，让阴影退居次席，突出文字与图标本身。
* **③ 改完是什么效果**：
  切到紧凑模式后，密密麻麻的书签不再像被一大堆黑色重阴影糊住视线，而是像一本排版密实紧凑的《商务印书馆辞海》索引页，字字分明、轻盈透气，既有一屏尽览海量书签的极高密度，又保留了纸墨的干爽。
* **④ 代价与风险**：
  极小。仅在 `.compact-view .card` 规则下覆盖一行 `box-shadow` 与 `border`，改动 2 行 CSS。

---

### 提案 3.4：二级子分类与主分类排版平铺，缺乏纵深阶梯感
* **① 现在长什么样、有什么别扭**：
  在支持二级分类后，子分类在主画面中仅表现为 `margin-top: -6px`、字号小一点点，并贴了一个小标签「隶属 XX」。但它的左侧起始位置与父级分类 100% 顶格平齐，底下的卡片也是直接平铺。用户在长页面滚动时，很难一眼分辨出这一截内容到底是平级的下一辑，还是上一辑的子目录，各级分区的上下级隶属关系全靠肉眼去读那几个小字。
* **② 打算怎么改**：
  为子分区（`.section--sub`）引入传统的「编纂层级缩进」：左侧整体内缩 16px～20px，并在左边缘挂一根雅致的 1.5px 墨色层级垂线（如同字典目录树的引线或书脊内折线），标题前缀「01·」与隶属标签收拢为规范的层级标题样式。
* **③ 改完是什么效果**：
  往下滑动时，顶级大分类如大树主干横贯整屏，而子分类如同分支枝桠工工整整缩进在父级下方，左侧一条细墨线清清楚楚拉出从属关系，读者扫一眼就能看懂结构，无需费神辨认。
* **④ 代价与风险**：
  小。修改 `.section--sub` 的 `margin-left` 与左侧轻量边框，不影响现有的分类遍历与滚动监听。

## 四、字母索引与侧栏（A-Z strip & Sidebar）

### 提案 4.1：侧栏索引胶囊圆角与徽标药丸（Pill Badges）破坏古籍目录沉浸感
* **① 现在长什么样、有什么别扭**：
  左侧吸顶侧栏 `.sidebar-index` 整体是个棱角分明的深黑硬边框纸墨盒子（`border: 2.5px solid var(--ink)`）。但是盒子里面的导航链接（`.sidebar-link`）被设置了 `border-radius: 6px`，右边的统计数字徽标（`.sidebar-badge`）更是直接使用了现代 App 烂大街的 `border-radius: 10px` 椭圆药丸。高亮激活项选定后，像在报纸目录上贴了一块圆滑的现代塑料胶布，跟整个编辑墨线的大氛围格格不入。
* **② 打算怎么改**：
  将侧栏目录全面「书目化」：
  1. 取消 `.sidebar-link` 的 6px 圆角，改用直角书签条（激活时以整洁的墨底白字方块或左侧朱砂竖线标出）；
  2. 取消 `.sidebar-badge` 的现代跑道型椭圆胶囊，改用古籍方块印记，如方角框 `[ 12 ]` 或直接用衬线小数字点缀；
  3. 目录项与右侧数字之间可选用经典的「编辑点阵引线（Dot Leader: . . . . . . ）」对齐，重塑真正的出版物目录仪式感。
* **③ 改完是什么效果**：
  左侧吸顶栏不再像一个从后台管理系统（Admin Dashboard）生硬搬过来的侧边菜单，而是变成了像一册线装字典或古籍珍本的「卷次总目」，古朴厚重、秩序井然。
* **④ 代价与风险**：
  极小。仅改动侧栏链接与徽标的 CSS 圆角与边框，不改动任何 DOM 结构与滚动监听逻辑。

### 提案 4.2：字母滑轨提示栏中的黄色打字机闪电 Emoji（⚡）现代杂质剔除
* **① 现在长什么样、有什么别扭**：
  A-Z 快速定位栏右侧的提示文字开头，塞了一个黄灿灿的打字机通用 Emoji 符号 `⚡`（`<span class="hint-dot">⚡</span>`）。在全站深墨、米纸、赭石构成的古朴编辑版面中，这个鲜艳的黄色 Emoji 极其刺眼出戏，像是在严肃的报刊版面上画了一笔荧光水彩笔，瞬间拉低了质感。
* **② 打算怎么改**：
  将现代通用的 `⚡` 符号换成中式排版或书籍编校专用标记，例如「※」（校勘标星号）、「❖」（金石花星）、「§」（节号）、或者小巧的纯 CSS 赭石墨线点标。
* **③ 改完是什么效果**：
  提示行前不再闪着一颗廉价刺眼的现代黄色 Emoji，而是浮现出一枚内敛低调的书刊校勘小符号，文字自然融入纸墨底色，浑然天成。
* **④ 代价与风险**：
  零风险。仅替换 HTML 中单字符，或在 CSS 中微调其颜色，无任何逻辑波及。

## 五、页脚（Footer）

### 提案 5.1：刊底收束单薄，缺少与大报头双墨线呼应的「收卷墨规」
* **① 现在长什么样、有什么别扭**：
  首屏顶部大报头下方，有一道极具仪式感的经典报刊双墨线（`.rule-double`：上粗 3.5px、下细 1px）。但滑到页面最底部时，页脚（`.footer`）上方却只有一根干瘪孤单的 `2px solid var(--ink)` 普通单横线。整份长达几千像素的长画卷，开头气势磅礴，结尾却草草收工，上下未能形成呼应，缺乏古籍合卷、刊物封底的仪式感。
* **② 打算怎么改**：
  在页脚上方引入与报头镜像对称的「刊底双墨线」（上细 1px、下粗 3.5px），在落款下方增设合卷底线，实现「首尾相顾、开阖自如」的刊物装帧闭环；同时将第二行落款「本辑已毕 · 下辑随缘」由现在的左下角散漫平铺，调整为居中题跋排版或带有金石钤印感的收卷结语（牢牢保证原文字一字不动）。
* **③ 改完是什么效果**：
  滑到页面最底端时，不再感觉是网页内容戛然而止，而是像读完了一整份装订严整的年度特刊：上方有开篇报头双线，底端有收尾双墨线结界，两行落款如同碑帖末尾的题跋款识，整卷合拢，圆满端庄。
* **④ 代价与风险**：
  极小。仅为 `.footer` 调整顶边线的双线样式及居中文案微调，牢牢恪守用户要求的两行原落款文字一字不改。

## 六、夜间模式（Night Mode / 沉墨）

### 提案 6.1：白天图标直接投掷夜间，造成刺眼的「荧光斑马线效应」
* **① 现在长什么样、有什么别扭**：
  切换到夜间「沉墨」模式后，全站背景变成了近乎全黑的炭墨深色（`#100f0e`），卡片也是暗沉的 `#171514`。但每个书签的图标框（`.icon-box`）在夜间模式下仍然顽固地维持着纯白底色（`#ffffff`）！一屏几十个甚至上百个卡片，几十块刺眼的高亮白色小灯泡整齐划一地刺向眼睛，夜间阅读本该沉静温润，结果被一堆白晃晃的小方块照得眼花缭乱。
* **② 打算怎么改**：
  在不新增、不更改既有配色变量的前提下，于夜间模式（`html.dark-theme .icon-box`）下优化图标呈现：
  1. 将图标背景由纯白平移至深色书房预设的 `--box-bg`（`#201e1c`）或 `--card-hover`，边框使用 `--border-line`；
  2. 对外链白底彩标施加轻度柔光滤镜（如 `filter: brightness(0.88) contrast(0.95)`），消除白色硬边切入深黑背景时的荧光毛刺感；而首字兜底图标则自然浸润在沉墨底色中。
* **③ 改完是什么效果**：
  深夜切到沉墨模式后，卡片左侧不再像挂着一排刺眼的远光灯，而是变成了一枚枚如同印在玄纸、深木上的暗色徽印，图标柔和克制，整体墨香浓郁、温润护眼。
* **④ 代价与风险**：
  极小。仅在 `public/style.css` 现有的 `dark-theme` 作用域下补充 `.icon-box` 的夜间渲染规则，不改动图片来源与 DOM 结构。

### 提案 6.2：夜间卡片重黑阴影「凭空隐形」，卡片退化为刺眼冷线框
* **① 现在长什么样、有什么别扭**：
  在白天模式下，卡片有着非常好看的 4px 墨规实体投影（`rgba(39, 36, 34, 0.88)`）。但在夜间模式下，页底变量是 `#100f0e`，卡片是 `#171514`，而阴影变量 `--card-shadow` 被定为了 `#050404`。人眼在黑暗中根本分不清 `#10`、`#17` 与 `#05` 的区别，4px 实体阴影在夜间完全融进了黑底里，等于彻底消失！与此形成鲜明反差的是，卡片边框却使用了极亮的暖白 `--ink`（`#e6dfd3`，100% 不透明度）。导致夜间模式下卡片完全没有立体沉纸感，只剩下一堆刺眼的白色荧光骨架，极其干冷。
* **② 打算怎么改**：
  在夜间模式下，将常态卡片的边框收敛为静谧的 `--border-line`（`rgba(230, 223, 211, 0.16)`），让黑夜里的白色线框不那么耀眼；同时将卡片阴影从不可见的纯黑块，巧妙借用既有的 `--ochre` 琥珀温光（如 `3px 3px 0 rgba(217, 111, 71, 0.25)`，或悬停时绽放琥珀光泽）。
* **③ 改完是什么效果**：
  夜间模式下的卡片不再是一群冷冰冰、刺眼的白色火柴盒，而是如同书桌暗光下一页页带有微弱赭石印泥厚度的深黑素笺，暗部层峦叠嶂，文字柔和清晰。
* **④ 代价与风险**：
  小。仅微调夜间模式下 `.card` 的常规描边与微投影透明度，完全在既有变量取值范围内运作。

## 七、移动端（Mobile Adaptation）

### 提案 7.1：手机顶栏三按钮同挤一行引发文本折行溢出
* **① 现在长什么样、有什么别扭**：
  在屏幕宽度小于 540px 的手机端，工具栏下方的「添加网站」、「紧凑模式」、「导入书签」三个按钮被设置了同行的弹性伸缩（`flex: 1`）。在 375px 或更窄的手机上，三块带有图标与长文本的厚边框按钮硬挤在同一排，按钮里的汉字被挤到两头甚至文字被动折行，显得拥挤不堪；而「导入书签」在手机上几乎没有真实使用场景，却常年霸占宝贵的手机首屏三分之一宽度。
* **② 打算怎么改**：
  优化移动端工具栏空间编排：
  1. 手机端将使用频度极低的「导入书签」收拢为右上角的紧凑图标按钮或暂时退避至次级菜单；
  2. 让每日最核心的「＋添加网站」占主轴，「紧凑/舒适切换」作为辅控，形成舒展的半半平分双按键，或者主按键横向贯通。
* **③ 改完是什么效果**：
  手机端打开后，不再看到三颗被挤得快要爆炸变形的局促小按键，而是主次分明、手指一碰就能准确定位的大气操作区，误触率骤降，界面舒展大方。
* **④ 代价与风险**：
  小。仅针对 `@media (max-width: 540px)` 调整按钮伸缩比与显隐逻辑，桌面端完全不受任何影响。

---

### 提案 7.2：手机端底留白高达 75vh 沦为「深渊虚空」
* **① 现在长什么样、有什么别扭**：
  在当前移动端 CSS 中（行 1360），写死了一条 `.main-sections-content { padding-bottom: 75vh !important; }`。原本意图是为了给滚动定位留出空间，但后果极为灾难：用户在手机上滑完最后一个分类后，必须在完全空白的屏幕上空转大半屏（75% 的屏幕高度纯白或纯黑），才能艰难滑到底部页脚。用户滑动时会误以为页面崩溃卡死、数据加载中断或到底了但刷不出来。
* **② 打算怎么改**：
  将极端的 `75vh` 虚空留白缩减至合理的安全滚动余量（如 `20vh`～`25vh`），并通过标准的 `scroll-margin-top`（现已设为 56px）保证置顶卡片能精准对齐吸顶栏。
* **③ 改完是什么效果**：
  手机滑到底部时，内容自然收束，紧接着就是工整的刊底落款，再也不会发生滑完书签后还要在一大片看不见底的空白虚空里划拉半天的滑稽体验。
* **④ 代价与风险**：
  极小。仅改动 1 个数值，彻底解决手机端“看似加载中断”的巨大视觉空洞。

## 八、动效与细节（Transitions, Micro-interactions & Polish）

### 提案 8.1：弹窗展开生硬如浏览器告警，缺乏纸墨铺展与落印质感
* **① 现在长什么样、有什么别扭**：
  点击「添加网站」时，弹窗（`.modal`）瞬间毫无过渡地弹在屏幕正中央，像极了古老的 Windows 报错弹窗或原生 alert；关闭时也是咔嚓一下生硬消失。在充满了墨线柔和过渡和纸本古韵的页面上，这种生硬的闪现完全破坏了文人案头的宁静感。
* **② 打算怎么改**：
  为弹窗加入极轻量（160ms～180ms）的纸墨舒展微动效：
  1. 展开时：从轻微缩放（`scale(0.96) translateY(-6px)`）伴随柔和淡入，如同在桌面上铺开一纸便笺；
  2. 弹窗保存按钮加入如同朱砂印章盖落的下沉微阻尼（配合 active 的按压），增强操作确定感；
  3. 弹窗背景暗幕加入优雅的微渐变淡入。
* **③ 改完是什么效果**：
  点击添加时，弹窗不再像个突兀弹出的广告，而是带着微微的宣纸舒展感平稳铺在视线中央；按下保存时，按钮像一颗扎扎实实的印章盖在纸面上，操作充满手工质感。
* **④ 代价与风险**：
  小。仅增加 CSS `@keyframes` 与 transition 规则，不改动弹窗的表单验证与数据写入逻辑。

---

### 提案 8.2：搜索框清空按钮突兀闪现，建议加入温和淡入淡出
* **① 现在长什么样、有什么别扭**：
  在搜索框输入文字时，右侧的清空按钮 `✕`（`.clear-btn`）是通过 JS 直接强行切换 `display: none` 和 `display: block`。这就导致每敲一个字符，如果从空到有，黑色的小叉叉会硬生生瞬间扎在输入框末尾，没有任何过渡，视觉体验相当生硬。
* **② 打算怎么改**：
  将清空按钮的显隐从粗暴的 `display: none` 改为基于 `opacity` 与 `visibility` 的轻缓过渡（0.12s），输入文字时小叉叉如墨水化开般自然浮现，清空后轻柔隐退。
* **③ 改完是什么效果**：
  打字检索时，右侧的清空操作符平滑浮出，不再有突如其来的硬闪跳跃，输入心流更加丝滑平稳。
* **④ 代价与风险**：
  极小。几行 CSS 过渡微调，完全不影响原有的点击清空与搜索重置功能。
